# Acceptance Protocol — Defensive-Language Pass (v0.2.0)

This folder makes the acceptance test for the defensive-language feature reproducible and independent. The protocol was revised after an independent verifier found that the first acceptance set duplicated the skill's own worked examples. The final set uses four **unseen** drafts and a **blind** copy of the skill.

## What is tested

| Case | Genre | What a pass requires |
|------|-------|----------------------|
| `academic_hedge_stack_discussion` | Academic Discussion | Cut stacked hedges and reflexive limits; keep design, numbers, CI, p value, and association strength; no causal upgrade |
| `academic_calibrated_cohort` | Academic calibrated paragraph | Remove one throat-clearing frame; keep every real caveat, interval, and disclosure; make almost no other change |
| `narrative_letter_scene` | Third-person fiction | Remove reader management and authorial reassurance; render the unease through gesture and body language; keep Elias and the letter; add no objects, dialogue, or plot events |
| `email_budget_check_in` | Professional email | Cut apology and permission-seeking; keep recipient, budget, and deadline |

Each case has a machine-checkable subset (marker counts, must-keep patterns, forbidden claims, length, restraint) and a human-judgment subset scored by the verifier (voice, judgment, calibration).

## Directory layout

- `cases.json` — prompts, drafts, machine checks, notes; frozen before output generation
- `inputs/` — the only case files the rewriter sees (prompt + draft, no assertions)
- `outputs/` — rewrites generated by the rewriter from the blind copy
- `report.json` — automated metric result written by `check_outputs.py`; includes the `cases.json` SHA-256
- `rubric.md` — independent scoring rubric and hard gates
- `review/` — independent verifier report
- `stage_blind.py` — builds the blind skill copy (no `evals/`, no `references/examples.md`)
- `check_outputs.py` — deterministic metric checker
- `archive/` — superseded exploratory rounds, retained for provenance only

## Procedure

### 1. Freeze the cases

`cases.json` must not be edited after the rewriter starts. Record its SHA-256:

```bash
python3 -c "import hashlib,pathlib;print(hashlib.sha256(pathlib.Path('evals/acceptance/cases.json').read_bytes()).hexdigest())"
```

`check_outputs.py` writes the same hash into `report.json`, so a report generated from a different case file is detectable.

### 2. Static validation

```bash
python3 evals/validate_skill.py
```

Must exit 0. The validator checks that acceptance inputs do not appear anywhere in the skill docs or `evals/evals.json` (anti-target-fitting), that no-invention and anti-compression rules are present, and that the narrative length floor is at least 0.67 (the one-third-shrink boundary).

### 3. Behavioral test (independent rewriter, blind copy)

```bash
python3 evals/acceptance/stage_blind.py --out /tmp/humanize-writing-blind
```

Give the rewriter only the staged directory. It contains `SKILL.md`, the reference docs, the example style profile, `inputs/`, and an empty `outputs/`. It does **not** contain `evals/`, `references/examples.md`, `cases.json`, the rubric, the reports, or the scores.

Instruction to the rewriter: follow the skill exactly; handle each input independently; write only the final rewritten text to `outputs/<case-id>.md`; do not read outside the blind directory; do not copy wording from any example.

Copy the produced files into `evals/acceptance/outputs/`.

### 4. Automated checks

```bash
python3 evals/acceptance/check_outputs.py
```

Must exit 0 and write `report.json`. The checker requires every configured marker to appear in the input, so a typo cannot silently produce a vacuous test. The narrative case uses `[0.67, 1.20]`: 0.67 is the one-third-shrink boundary from the reference, and 1.20 allows rendered scenes to grow. The skill's usual guidance is 70–115%; acceptance allows the boundary and a small upper tolerance.

### 5. Independent verification

A fresh verifier receives `cases.json`, `inputs/`, `outputs/`, `report.json`, the rubric, the blind manifest, and the archive. It re-runs both scripts, re-derives the hard gates from the raw text, scores R1–R6, and writes `review/verifier_report.md` with severity-labelled findings. The verifier must not edit skill files or outputs.

### 6. Acceptance report

The Lead combines the static result, metric table, verifier scores, and any fixes into `ACCEPTANCE.md` at the repo root.

## Why this is meaningful

- **Unseen drafts**: no acceptance draft appears in the skill docs, examples, or `evals/evals.json`.
- **Blind copy**: the rewriter cannot read the test cases, assertions, rubric, reports, or `examples.md`. The staged reference still contains its generic worked before/after examples in section 4, so this is blind to the test set rather than strictly answer-key-free.
- **Worked examples**: the full reference keeps its examples (useful for users), and the new narrative draft is template-adjacent to the generic narrative example. Output-copying is checked by the verifier; this is disclosed as a residual risk.
- **Independent rewriter and verifier**: the author does not hand-write the passing outputs or score the feature.
- **Dual checks**: deterministic gates catch fact loss and metric gaming; the rubric catches tone, overcorrection, and bad judgment that regexes miss.
- **Restraint case**: one case is deliberately already calibrated. A skill that always over-edits will fail it.
- **Frozen cases**: the case hash is recorded in the report, and superseded rounds are archived.

## Known limits

- Four cases cannot cover every genre or every field convention.
- Regex marker counts are a proxy; they can miss paraphrased defensiveness and can flag legitimate uses.
- The verifier is an LLM agent, not a human editor; its scores are evidence, not a guarantee.
- Stylistic naturalness remains a judgment call. The skill should be applied with a human in the loop for publication work.
